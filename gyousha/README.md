# 匠協コネクト（工務店 × 協力業者 の依頼・連絡アプリ）

工務店が自社の協力業者（下請け）を管理し、**作業依頼**や**一斉お知らせ**を送信。協力業者は**招待リンク**を開くだけで（登録不要）、依頼に**「受ける／不可」＋一言**で返信できます。「匠コネクト（工務店間の職人シェア）」の姉妹版です。

## 2つのアプリ

| ファイル | 役割 | 色 |
|---|---|---|
| `admin.html` | **工務店側（管理）**：協力業者の名簿管理・作業依頼・一斉お知らせ・返信確認・招待リンク発行 | 紺 |
| `index.html` | **協力業者側（利用者）**：招待リンクで開き、依頼に返信・お知らせ閲覧 | オレンジ |

補助ファイル：`config.js`（設定・業種マスタ）／`data.js`（Firebase・お試し・体験の自動切替）／`common.js`（共通処理）／`styles.css`／`sw.js`・`manifest*.json`（PWA）。

> アイコンは親アプリ「匠コネクト」と連動した紺＋オレンジで、大きな「協」。工務店側＝紺、協力業者側＝オレンジ。

## 扱う情報（協力業者ごと）
- **業種**：個人事業主大工／電気工事／水道設備／塗装／内装／左官／屋根瓦／屋根板金／足場／外構／基礎／外壁／防水／その他（自由記述）
- 業者名（必須）・電話・担当者・対応エリア・メモ・★よく使う

> **扱わない情報**（方針）：職人の個人情報／単価／空き日カレンダー／資格。連絡と依頼のやり取りに特化。

## 3つの動作モード（自動切替）
1. **共有モード（本番）**：`config.js` に Firebase 設定があるとき。工務店と協力業者がリアルタイムに共有。協力業者は招待リンク＋匿名サインインで参加（ログイン不要）。
2. **お試しモード**：Firebase 未設定（`apiKey` が空）のとき。その端末内だけで動作（他端末とは共有されません）。
3. **体験版**：URL に `?demo=1` を付けたとき。サンプル入りのサンドボックス（24時間で自動リセット）。`admin.html?demo=1` と `index.html?demo=1` は同じ体験データを共有し、依頼→返信の流れを試せます。

## 使い方（本番）
1. 工務店が `admin.html` を開き、**自社名を登録** →「管理リンク（`admin.html?c=…`）」をブックマーク（別端末でも同じ会社を管理できます）。
2. 「業者」タブで協力業者を登録。各カードの **📲招待** から、その業者専用の招待リンク（`index.html?c=…&b=…`）を LINE 等で送付。
3. 協力業者はリンクを開くだけで自分宛の**依頼・お知らせ**を確認し、**受ける／不可＋一言**で返信。
4. 工務店の「依頼」タブに返信が反映（バッジ表示）。「お知らせ」タブから全員／業種別に一斉配信も可能。

## 【必須】Firebase の設定（共有モードで使う場合）

**(1) 認証**：Firebaseコンソール → Authentication → ログイン方法で **「匿名（Anonymous）」を有効化**（協力業者はログイン不要のため匿名を使います）。

**(2) Realtime Database → ルール**：このアプリは Firebase 内の **`takyo/`** パスを使います。オセロ／勤怠／匠コネクトと同じプロジェクトを流用できますが、**ルールは全体を置き換える**ため、既存の `rooms`／`kintai`／`shokunin` を消さないよう、下記の `takyo` ブロックを**既存ルールに追加**してください（他アプリのルールは `shokunin/README.md` を参照）。

```json
"takyo": {
  "companies": {
    "$ck": {
      ".read": "auth != null",
      ".write": "auth != null"
    }
  }
}
```

- **列挙防止**：`.read` を会社（`$ck`）の階層だけに置き、親（`companies`／`takyo`）には置かないのが要点です。これにより「**会社キー（招待リンクに含まれる）を知っている人だけ**がその会社のデータを読める」capability 方式になり、全社の一覧取得（スクレイピング）はできません。
- **段階導入**：まず動作確認したいだけなら `"takyo": { ".read": "auth != null", ".write": "auth != null" }` でも動きますが、これは全社を列挙できてしまうため本番では上の `$ck` 限定を使ってください。

> **セキュリティの割り切り（重要）**：この方式では、招待リンク（会社キー）を渡した相手はその会社のデータを読み書きできます。信頼できる自社の協力業者に配る前提の簡易モデルです。より厳格にするには、①`.validate` で「協力業者は自分の依頼の `reply` だけ書ける」等に制限、②協力業者もメール/パスワードでログイン、③Firebase App Check 導入、を検討してください（`shokunin/README.md` の該当節が参考になります）。リンクは不特定多数に公開しないでください。

**(3) 反映**：ルール公開後、反映まで数十秒かかることがあります。

## ローカルで確認する
PowerShell で `serve.ps1` を実行 → `http://localhost:8770/`。
- 体験版：`http://localhost:8770/admin.html?demo=1` と `…/index.html?demo=1`
- お試し：`config.js` の `firebase.apiKey` を空にすると端末内モードになります（同じブラウザなら admin と index が同じデータを共有＝1台で連携確認できます）。

## 公開（GitHub Pages 等）
静的ファイルのみ。`gyousha/` を置くだけで動作します（サーバー不要）。共有モードには上記 Firebase 設定が必要です。

## メモ
- 版を上げるときは `config.js` の `appVersion`、各 HTML の `?v=`、`sw.js` の版を揃えてください。
- 業種は `config.js` の `trades` で追加・変更できます（登録済みデータはそのまま）。
